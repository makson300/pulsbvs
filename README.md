# Пульс БВС

Первый интерфейс и аналитическое ядро платформы предиктивного контроля агродронов DJI AGRAS. Проект намеренно начинает с проверки качества данных: выводы строятся только по полям, действительно присутствующим в импортированном журнале.

## Запуск

```bash
npm install
npm run dev
```

Для production-сборки:

```bash
npm run build
```

## Подтверждённые ориентиры для DJI AGRAS T40

Источники: [руководство DJI AGRAS T40/T20P](https://dl.djicdn.com/downloads/t40_t20p/20221021multi/T40_T20P_User_Manual_v1.0_EN.pdf) и [чек-лист обслуживания DJI](https://ag.dji.com/newsroom/agras-t40-preseason-maintenance-guide).

- Батарея выполняет самодиагностику напряжения, тока и температуры; ошибки сохраняются в батарее.
- DJI указывает критическое напряжение пакета **47,6 В**: при нём аппарат автоматически снижается и садится.
- Диапазон эксплуатации батареи: **-5…45 °C**; свыше **50 °C** DJI предупреждает о риске возгорания/взрыва.
- Не использовать повреждённую, вздутую, протекающую, упавшую или побывавшую в воде батарею; не летать ниже 15% заряда.
- Ранние признаки проблем моторов, подтверждённые DJI: сопротивление или неровность при ручном вращении — возможны коррозия обмотки, повреждённый подшипник или другое повреждение.
- После каждых 100 полётов или 20 часов DJI требует регламентный осмотр.

## Важное ограничение логов

SmartFarm/KML пригоден для маршрута, скорости и активности распыления, но не гарантирует серийный номер батареи и глубинную телеметрию. Для предиктивной оценки батарей нужны исходные расширенные экспорты с T40 — в частности, доступные через DJI Assistant 2 for MG/пульт. Когда появится первый реальный лог, необходимо зафиксировать его структуру и написать конкретный адаптер парсинга.

Правила в `src/analytics/batteryRisk.ts` — консервативная первичная триаж-оценка, а не допуск к полёту и не замена требований DJI или диагностики специалистом.

## Статус и направление разработки

Сейчас это frontend-демо с рабочим импортом CSV/TXT/KML, проверкой качества данных, первичными правилами батарейных рисков, демо-активами дронов/батарей и историей поддерживаемых импортов в `localStorage`. DAT/ZIP принимаются честно, но не анализируются и не сохраняются как полноценный импорт до подключения отдельного декодера. Настоящих пользователей, базы данных и производственного backend пока нет.

Актуальное сопоставление с AirData, границы первого пилота и пересмотренная дорожная карта находятся в [PRODUCT_ANALYSIS.md](PRODUCT_ANALYSIS.md).

Backend пока не реализован. Для следующего этапа подготовлены проектные документы:

- [Контракт API будущего backend v1](docs/BACKEND_API_CONTRACT_V1.md): организации, пользователи, активы, импорты, полёты, алерты и задачи ТО.

Эти документы не означают, что backend, декодер DAT/ZIP или подтверждённый адаптер T40 уже существуют.
