Этот файл нужен, чтобы не терять контекст при сжатии истории, смене модели или перезапуске Harvi Code.

Для старта нового чата также подготовлен файл `NEXT_CHAT_BRIEF.md` — в нём есть готовый стартовый промпт и глобальная дорожная карта разработки.

## 1. Ключевая цель продукта

**Пульс БВС** — веб-продукт для контроля флота БВС/дронов и предиктивной диагностики, особенно батарей и эксплуатационных рисков.

Ориентир по ценности: Airdata-подобный продукт, но адаптированный под российский рынок, локальную эксплуатацию и реальные ограничения доступа к зарубежным сервисам/инструментам.

Первый фокус: предиктивные алерты по дронам и батареям. Важный целевой аппарат на следующих этапах — **DJI Agras T40**.

- При импорте пользователь выбирает дрон и батарею.
- Поддерживаемые CSV/TXT/KML импорты сохраняются в историю с именем файла, временем, активами, профилем, качеством, алертами и исходным результатом анализа.
- Сохранённый анализ можно открыть из «Истории импортов» после перезагрузки страницы.
- DAT/ZIP не создают полноценную запись истории, пока нет подтверждённого декодера.

### Импорт и аналитика

Поддерживается:

- CSV/TXT как табличная телеметрия;
- KML как маршрутный источник;
- DAT/ZIP принимаются как неподдержанные источники с честным сообщением: декодер ещё не подключён, аналитика не выполняется.

Аналитика умеет:

- определять доступные/отсутствующие поля;
- считать Data Quality Score;
- классифицировать источник импорта:
  - `csv`,
  - `kml`,
  - `unsupported` для DAT/ZIP,
  - `unknown`;
- показывать паспорт импорта:
  - маршрутный источник;
  - базовая батарейная телеметрия;
  - расширенная батарейная телеметрия;
- рекомендовать следующий лучший файл для более точной диагностики.
- давать пользователю скачиваемые примеры CSV и KML.

### Батарейные риски

Реализованы первые консервативные правила:

- ограниченные данные (`BATTERY_DATA_LIMITED`);
- разбаланс ячеек (`BATTERY_CELL_IMBALANCE`);
- перегрев батареи (`BATTERY_OVERHEAT`);
- критическое низкое напряжение (`BATTERY_UNDERVOLTAGE`);
- аномальная просадка напряжения (`BATTERY_VOLTAGE_SAG`);
- ускоренный разряд (`BATTERY_RAPID_DRAIN`);
- ошибка батареи в логе (`BATTERY_DEVICE_ERROR`).

Важно: эти правила — первичный triage, не замена официальной диагностике или инструкции DJI.

### Тестовая защита

Подключён `vitest@3.2.6`.

Покрыты тестами:

- route-only данные не обещают оценку батареи;
- T40 undervoltage ниже 47.6 В даёт critical alert;
- сильный разбаланс ячеек даёт critical alert;
- перегрев батареи даёт critical alert;
- CSV с ячейками определяется как расширенная батарейная телеметрия;
- KML парсится как маршрутный источник;
- CSV без ячеек определяется как базовая батарейная телеметрия.
- пустые и битые CSV/KML не создают фальшивых точек и батарейных выводов;
- DAT/ZIP не запускают фальшивую аналитику до появления отдельного декодера;
- доменная история импортов сохраняет поддерживаемый анализ и не создаёт полноценные записи для DAT/ZIP.

## 6. Проверенные факты по DJI Agras T40

- KML/SmartFarm полезны для маршрутов, скорости, зоны работ и активности, но часто недостаточны для глубокой батарейной диагностики.
- Для серьёзной предиктивной аналитики T40 нужны расширенные логи с дрона/пульта/обслуживания, желательно с напряжениями ячеек, температурой, предупреждениями, нагрузкой и историей батареи.
- Критическое напряжение пакета T40: **47.6 В** — ниже этого порога возможны сценарии автоматического снижения/посадки.
- Рискованные условия батареи: температура выше 50 °C, повреждения, вздутие, падение, вода/влага.
- Осмотр батареи важен каждые 100 полётов / 20 часов эксплуатации.
- Проблемы двигателя могут проявляться через шум, сопротивление, коррозию, подшипники и неровную работу.

## 11. Актуальная дорожная карта

Подробное обоснование и границы MVP — в `PRODUCT_ANALYSIS.md`. AirData используется как ориентир операционного контура «импорт → актив → риск → ТО → уведомление → отчёт», а не как перечень экранов для копирования.

1. **Основание пилота: активы и импорт — завершено в frontend-демо.** Реализованы доменные типы, демо-активы, выбор дрона/батареи, история поддерживаемых импортов в `localStorage` и открытие сохранённого анализа.
2. **Достоверный адаптер DJI Agras T40.** Получить обезличенные реальные журналы, зафиксировать схему, написать адаптер, профиль порогов и контрактные тесты. DAT/ZIP декодировать только после отдельного исследования формата.
3. **Backend-контур пилота.** Подготовить API-контракты по уже работающей локальной модели, выбрать PostgreSQL + единый Node backend через ADR, определить хранение оригиналов логов и on-prem требования.
4. **История батареи и ТО.** Накопить сравнимые полёты, показывать тенденции только при достаточной выборке, создавать и закрывать объяснимые задачи обслуживания.
5. **Операционная готовность.** Добавить карту/временную шкалу для доступной телеметрии, отчёты HTML/PDF/CSV, аудит и email/webhook-уведомления. Telegram не использовать.
6. **Масштабирование по спросу.** Мультиорганизационность, API, площадки, документы, чек-листы, дополнительные модели БВС и только затем дорогие функции наподобие streaming/планирования.

Первый следующий инкремент: описать API-контракты backend и ADR стека, параллельно подготовив требования к реальным обезличенным логам DJI Agras T40.
