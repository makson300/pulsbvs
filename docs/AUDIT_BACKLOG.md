# Пульс БВС — задачи после технического аудита

Этот список фиксирует работы, которые нельзя корректно закрыть внутри текущего frontend-демо без подтверждённых источников данных или серверного контура. Он не является обещанием реализованной функциональности.

## Приоритет 1 — достоверность данных

1. **Получить обезличенные журналы одной модели текущего парка.** Нужны разрешённые образцы Avata 2, Avata 360 или Mini 4 Pro вместе с происхождением файла, версиями ПО, единицами и перечнем полей. Оригиналы журналов не коммитить.
2. **Зафиксировать схему и профиль модели.** Для подтверждённого источника описать обязательные поля, единицы, диапазоны, коды предупреждений и ссылки на основания порогов.
3. **Создать отдельный разбор подтверждённого формата.** Добавить обезличенные фикстуры и контрактные тесты. DAT/ZIP/JSON не читать до такого исследования.
4. **Включить модельные правила только после профиля.** В частности, порог низкого напряжения и расшифровка предупреждений должны приходить из подтверждённого профиля, а не из универсального CSV-разбора.

## Приоритет 2 — надёжное хранение и доступ

1. Реализовать серверный контур по [контракту API](BACKEND_API_CONTRACT_V1.md) и [ADR 0001](adr/0001-node-postgresql-backend.md): организации, пользователи, роли, активы и импорты.
2. Добавить безопасное хранение оригиналов, контроль доступа, ограничение размеров и типов файлов, проверку вредоносных вложений, аудит действий, резервное копирование и политику хранения.
3. Перенести локальные записи из браузера в серверное хранилище без потери связей «файл — дрон — батарея — карточка происхождения».

## Приоритет 3 — полезные рабочие процессы

1. Реализовать настоящие задачи обслуживания: создание из подтверждённых алертов, исполнитель, статусы, решение инженера и приложенные заметки.
2. Добавить тенденции батареи только при достаточном числе сопоставимых полётов и с объяснением выборки.
3. Добавить карту, временную шкалу и отчёты только для телеметрии, которая действительно присутствует в подтверждённом источнике.
4. Добавить email/webhook-уведомления после серверного контура. Telegram не использовать.

## Приоритет 4 — инженерная гигиена

1. **Выполнено: добавить узкую статическую проверку.** `npm run lint` запускает Biome и запрещает неиспользуемые импорты/переменные и non-null утверждения. Полный набор правил требует отдельного accessibility/layout-pass, чтобы не смешивать его с текущим этапом.
2. Ввести автоматический браузерный smoke в CI после появления серверного контура и стабильных тестовых данных.
3. **Выполнено: честно показать недоступность localStorage.** Кабинет выводит предупреждение, если браузер не даёт сохранять локальное состояние; сценарий покрыт Playwright-тестом. Это не заменяет серверное хранение, восстановление или экспорт.
